# Keos SRE Agent — v1.0.0-rc.1 Release Notes

**Tag:** `v1.0.0-rc.1` · **Date:** 2026-06-01 · **Status:** first release
candidate, architect review

This is the first cut of Keos that an external reviewer can `helm install`
from a tagged image. Everything that lands in `1.0.0` is expected to be
non-breaking on top of this; the suffix exists so the rc → GA transition
is a tag bump, not a code change.

---

## Highlights

### Production hardening across the chart
Every workload sets `runAsNonRoot`, `readOnlyRootFilesystem`,
`allowPrivilegeEscalation: false`, drops ALL capabilities, and uses the
`RuntimeDefault` seccomp profile. Liveness, readiness, and startup probes
are wired on every Deployment. PodDisruptionBudgets gate api + mcp-server
restarts. NetworkPolicies (4 of them) lock the namespace down to its own
data plane. Bearer tokens come from a projected K8s Secret via
`SHP_API_TOKEN_FILE`; comparison is constant-time. A custom rate-limit
middleware (120 req/min/IP, exempt for probes + `/metrics`) survives
burst traffic without dropping K8s health checks.

### Operability you can actually point at
12 named Prometheus metrics covering graph runs, LLM latency, OPA
decisions, escalations, approvals, observer events + errors, NATS depth,
and the agent mode. JSON-structured logs via `python-json-logger` (one
line == one record, parseable by jq / Loki / Datadog without grok).
Optional `ServiceMonitor` CR for clusters with Prometheus Operator.
`docs/OBSERVABILITY.md` ships alert rules + LogQL recipes.

### CI/CD pipeline matching the chart's surface area
`.github/workflows/ci.yml` — 9 jobs on every PR: ruff lint + mypy
typecheck (matrix 3.11 + 3.12), pytest with coverage, frontend lint +
typecheck + build, helm lint + kubeconform template-validate, opa-test
on `policies/`, docker build. `release.yml` on `v*` tags: multi-arch
buildx push to GHCR, cosign keyless OIDC signing, syft SBOMs as
attestations, helm chart pushed as an OCI artifact, auto-generated
release notes. Dependabot configured for pip, npm, docker, github-actions.

### Reliability hardening
- LLM (Ollama) calls retry 3× with 1/2/4 s exponential backoff; final
  failure routes to `escalate` with metric+reason, never crashes.
- Vector search (Qdrant) retries 3× then returns `[]` — graph continues
  with no RAG context (more likely to escalate defensively).
- OPA fail-closed contract preserved and explicitly tested
  (`tests/test_reliability.py`).
- SIGTERM / SIGINT handlers drain in-flight graph runs (up to 60 s) before
  exit. No more orphaned NATS messages on `kubectl rollout restart`.

### Data lifecycle
Audit log rotates daily via `TimedRotatingFileHandler`; `verify_audit_log()`
walks all rotated siblings so the HMAC chain stays verifiable across
rotation. Background retention loop sweeps incident JSON + trace JSONL
files older than configurable thresholds. Optional Velero `Schedule` CR
gated on `backup.velero.enabled`. `docs/BACKUP_RESTORE.md` documents a
tested restore drill.

### Governance + operational paper trail
- LICENSE policy + `CONTRIBUTING.md`, `SECURITY.md`, `CODEOWNERS`,
  `CHANGELOG.md`, PR template, 3 issue templates.
- 10 operational runbooks under `docs/RUNBOOKS/`, uniform 5-section
  template, with a decision-tree README that maps symptoms to runbooks.
- Disaster recovery defines a 30-minute RTO with three restore paths
  (Velero / manual tar / no-backup graceful degrade).

### GPU / Jetson runtime story
`ollama.gpu.*` Helm value block + conditional `runtimeClassName` +
resource limit rendering. `docs/JETSON.md` walks through Orin Nano 8 GB
end-to-end (k3s install, NVIDIA Container Toolkit, device plugin,
Pocteo install with GPU enabled). Perf: ~4-5 min CPU → 20-30 s on GPU
for a typical incident.

## Install

### Helm (preferred)

```bash
helm install pocteo oci://ghcr.io/your-org/charts/pocteo \
    --version 1.0.0-rc.1 \
    --namespace pocteo --create-namespace \
    --set-string auth.apiToken="$(openssl rand -base64 32)" \
    --set-string auth.hmacKey="$(openssl rand -base64 32)" \
    --wait --timeout 10m
```

### Laptop demo (docker-compose)

```bash
make demo-ui
# Open http://localhost — paste the token from .env.local
```

### Jetson Orin Nano with GPU

```bash
helm install pocteo oci://ghcr.io/your-org/charts/pocteo \
    --version 1.0.0-rc.1 \
    --namespace pocteo --create-namespace \
    --set ollama.gpu.enabled=true \
    --set ollama.gpu.runtimeClassName=nvidia
```

See [`docs/JETSON.md`](/docs/platforms/jetson) for the full hardware + driver setup.

### Talos

See [`docs/TALOS.md`](/docs/platforms/talos) — Chaos Mesh's containerd socket path
needs to point at `/run/containerd/containerd.sock` (NOT
`/run/k3s/...`).

  http://localhost/api/usecases/lib-memory-leak/run

## Known limitations

- **Single-replica api + mcp-server.** PDBs are wired with
  `minAvailable: 0` to make the upgrade-time-zero-availability explicit.
  HA story (leader-elect on the NATS consumer + multi-replica rate-limit
  with redis backend) is post-1.0.
- **Bearer token is shared.** Per-operator JWT auth — and the audit
  trail "who clicked Approve" — is on the post-1.0 roadmap. See
  `SECURITY.md §Hardening checklist` item 7.
- **K8sGPT MCP gateway** is the supported integration path; falls back
  to graceful degrade if it's unreachable. Direct gRPC is not exercised.
- **GPU support is NVIDIA only** (no AMD ROCm, no Intel oneAPI). Jetson
  is the validated path; other CUDA-capable hardware should work but
  hasn't been smoke-tested.
- **Chaos Mesh** v2.7.x is the pinned sub-chart. Newer majors of
  Chaos Mesh may rename the CRD fields the use-case wizard renders;
  not handled automatically.
- **Audit HMAC key rotation breaks chain verification of pre-rotation
  records** unless you preserve the old key. See
  `docs/RUNBOOKS/secret-rotation.md`.

## Architect review checklist (the why-this-tag)

When you walk this with the architect, the highest-signal entry points:

1. `policies/agent.rego` — the OPA matrix. The whole trust model
   collapses to "what does this matrix say?".
2. `agent/graph.py` — the LangGraph state machine. 9 nodes, one
   conditional edge, no recursion.
3. `agent/audit.py` — HMAC chain. `verify_audit_log()` is the proof.
4. `deploy/helm/pocteo/values.yaml` — every operational knob, documented
   inline.
5. `docs/RUNBOOKS/README.md` — the symptom→runbook decision tree shows
   the operational surface.
6. `docs/USER_GUIDE.md` — the 30-page reviewer-facing document.

If something here doesn't survive the review, the rc → GA delta will
record it. That's why it's an rc, not a final cut.
